# 🎯 まとあてシューティング — 要件書 README（詳細リファレンス）

このファイルは、**お客さん（生徒）役が要望を書き込んでいく「たった1枚の要件書」**です。
実際の授業では、この README を生徒が編集しながら要望を追記し、
プログラマー役がそれを読んでAIに指示 → 実装 → 動かして確認、を繰り返して
ゲームを完成させていきます。プログラマー役は自分でコードを1行も書かず、
**「READMEに書かれた要望をAIに伝える」ことだけ**でゲームを作っていきます。

## 使い方

1. お客さん役は「📝 今の要望」を書く・書き足す・書き換える。
2. プログラマー役は「📝 今の要望」を読み、AIに伝えて実装してもらう。
3. 実装できたら動かして確認し、「✅ 更新履歴」に一言メモを追記する。
4. お客さんの感想を聞き、また1に戻る。

## 🔍 実装時のカンニングペーパー（進行役限定・重要）

**「今の要望」の文章だけでAIに実装させると、クラスやAIセッションごとに見た目・数値が
バラつくことが検証でわかっています**（同じ要望文でも、技術選定・的やリングのデザイン・
HP/スコアなどの数値は毎回AIが自分で判断し直すため）。授業本番で生徒ごとの完成度に
差が出すぎないよう、プログラマー役は実装を依頼する際、必ず以下もAIに読ませてください
（生徒に見せる必要はありません。README.mdの「今の要望」を読ませたあとに、
追加で下記も参照させる、という使い方です）。

- **技術スタック**：A-Frame 1.5.0（`<script src="https://aframe.io/releases/1.5.0/aframe.min.js">`）。
  単一HTMLファイル、ビルド不要。詳細は `../guides/00_overview.md` 参照。
- **当たり判定の仕組み**：照準（リング）は画面中央に固定し、敵の方が左右に動いて
  中心を横切る。プレイヤーがマウスで狙う方式ではない。判定方法（raycasterかピクセル距離か）
  や照準リングのデザインは `../guides/00_overview.md`（パターン1）と対応する
  `../checkpoints/0N_*.html` の実装に合わせる。
- **各段階の「正解」実装**：これから作る段階に対応する `../checkpoints/0N_*.html` を
  実装前に読ませ、的・ボス・王様の見た目（色・形・大きさ）や数値パラメータ
  （撃破数のしきい値、HP、1回あたりのスコア量、移動速度など）をできる限りこれに合わせて
  実装するよう指示してください。「今の要望」に書かれていない細かい数値・デザインは
  AIの自由裁量ではなく、`checkpoints/` の実装を正としてください。
- **⚠️ 1つのチェックポイントファイルが複数ステップ分をまとめて含んでいることがある**：
  例えば `checkpoints/04_boss.html` は「中ボス（分裂）」と「ラスボス（ドラゴン＋HPバー）」の
  両方を1ファイルにまとめて含んでいます。しかし実際の授業やAIへの指示は
  Rev.3a（中ボスのみ）→ Rev.3b（ラスボスのみ）と**2回に分けて**行うため、
  Rev.3aの指示だけを渡した時に、チェックポイントに見えているラスボス部分まで
  AIが先回りして実装してしまわないよう注意してください。「今の要望・今回の指示で
  頼まれた範囲だけ」を実装し、チェックポイントの残りの部分は次の指示が来るまで
  手を付けない、という境界を明確にAIに伝えることが重要です。

### Rev.4（⑤改造タイム — ここからは決まった要望なし）

- ゲームが完成したので、ここから先の「今の要望」に決まった正解はありません。
  **生徒自身がお客さん役になって、この README の「今の要望」欄に
  自由に書き足していく**フェーズです。
- 進行役は改造の一例として、「今の要望」に次の1行を試しに追記し、実装例を見せます。

  ```diff
  + ラスボスを倒した後、宇宙人が出てきて8秒間だけ無限にクリックしてスコアを稼げるようにしたい
  ```

- **プログラマー→AIへの指示**：
  「ラスボスの後に、もう1つ連打できるボーナスステージを追加してください。今度は違う
  キャラクター（宇宙人）が出てきて、8秒間クリックし放題にしてください。」
- 🔍 **カンニングペーパー**：`../checkpoints/05_kaizou_example.html`（あくまで改造の一例。
  ⑤以降は生徒の自由な要望が中心なので、この段階からはカンニングペーパーに
  合わせることより「要望を実装できているか」を優先してよい。この回はキャラクター＝王様、
  秒数＝5秒という前提を生徒の要望に合わせて宇宙人・8秒に変更した実例）
- **できたもの**：[`06_kaizou.html`](06_kaizou.html)
  （`health: Infinity`の「消えない敵」（宇宙人）＋8秒タイマー。05からの差分はボーナス

- **ここから生徒に伝えること**：
  「みんなも自分の『お客さん』になって、この README の『今の要望』に
  『こんなゲームにしたい！』を書き足してみましょう。色を変える、敵を増やす、
  時間を変える……何でもAIに相談してみてください。」

#### 改造アイデアの例（困っている班へのヒント）

- ボーナスタイムを5秒じゃなく10秒にする、または王様以外の的も混ぜる
- ラスボスの体力や動きを変えて、もっと強く（弱く）する
- 中ボスの分裂数を2体じゃなく4体、6体にする
- ミス（外れ）した回数を数えて、多いと減点するようにする
- 効果音やBGMを追加する
- スマホでもプレイしやすいようにボタンのサイズを調整する
